# LEGIONFORGE 7.3.5 (build 26124) — аудит и устранение ошибок

Дата: 2026-10. Источник ошибок: `ОШИБКИ.txt`. Объём: полный клон
`https://github.com/andreysf1983-maker/legionforge_12.git` без изменений исходного дерева,
далее — точечные доработки.

---

## 1. Ошибки из `ОШИБКИ.txt` и как они устранены

В логе три независимые проблемы: одна падает на **компиляции**, две — на **старте**
worldserver (ASSERT по данным клиента).

### 1.1. `error C2535` — дублирование объявлений в `Player.h`

```
Player.h(2050,21): error C2535: bool Player::IsCustomRace(uint8): функция-член уже определена или объявлена
Player.h(2051,22): error C2535: uint8 Player::GetCustomRaceBase(uint8): ...
Player.h(2052,23): error C2535: uint32 Player::GetCustomRaceTeam(uint8): ...
```

**Причина.** Блок комментария `[LEGIONFORGE CUSTOM-RACES]` вместе с тремя объявлениями
был продублирован при слиянии патча кастомных рас: одни и те же `static`-методы
объявлены в одном и том же классе дважды (MSVC C2535 «мember already defined or declared»).

**Исправление.** `core/src/server/game/Entities/Player/Player.h` — второй экземпляр блока
удалён, объявления остались в единственном числе. Реализации в `Player.cpp` не менялись.

### 1.2. `BATTLE_PET_SPECIES_MAX_ID` (ASSERT `DB2Stores.cpp:745`)

```
BattlePetSpecies.db2: MaxId=5003 -> строк 5004, а BATTLE_PET_SPECIES_MAX_ID=2164.
```

**Причина.** `GetNumRows() = MaxId + 1`; в этом dbc 5004 видов питомцев, ядро
рассчитано на предел чистого клиента 2164.

**Исправление.** `core/src/server/game/DataStores/DBCEnums.h`:
`#define BATTLE_PET_SPECIES_MAX_ID 5004`.
Константа используется только в ASSERT и в ёмкости входящего буфера
`KnownPets` (`AuctionHousePackets.h:280`), формат исходящих пакетов не меняется —
правка протокольно безопасна. Штатный инструмент проекта
`tools/set_pet_species_max_id.ps1 -Value 5004` делает ровно то же самое.

### 1.3. `MAX_DIFFICULTY` (ASSERT `DB2Stores.cpp:827`)

```
Difficulty.db2: MaxId=147 -> строк 148, а MAX_DIFFICULTY=35.
```

**Причина.** В `enum Difficulty` последним элементом стоял `MAX_DIFFICULTY`, то есть 35.

**Исправление.** `DBCEnums.h`: перед `MAX_DIFFICULTY` добавлено явное
`DIFFICULTY_RESERVED_MAX = 147`, поэтому `MAX_DIFFICULTY == 148 >= 148`.
Явное значение обязательно и для парсера `tools/check_db2_build.ps1` (он вычисляет
«максимум явных значений + 1»), без него проверка продолжала бы считать предел 35.

Сопутствующая правка, без которой подъём константы дал бы неопределённое поведение:

* `ConditionMgr.cpp` (`CONDITION_SPAWNMASK`) — `UI64LIT(1) << MAX_DIFFICULTY` при 148
  это сдвиг шире `uint64`. Сдвиг ограничен 63 битами через тернарный оператор.
* Массивы `m_boundInstances[MAX_DIFFICULTY]` (`Player.h:2348`, `Group.h:463`) расширяются
  автоматически и остаются корректными; другие массивы, адресуемые сложностью, используют
  отдельную константу `MAX_CREATURE_DIFFICULTIES` и не затронуты.

### 1.4. `TaxiMaskSize` (ASSERT `DB2Stores.cpp:1096`)

```
TaxiNodes.db2: строк 2283, нужно TaxiMaskSize>=286, а в ядре 258.
```

**Исправление.** `DBCEnums.h`: `#define TaxiMaskSize 286`.
Пакет `SMSG_SHOW_TAXI_NODES` передаёт длину массива явным `uint32` перед битами
(`TaxiPackets.cpp`, `ShowTaxiNodes::Write`), поэтому клиент корректно прочитает и 286 байт.

Дополнительно закрыт связанный дефект памяти: `PlayerTaxi::LoadTaxiMask` не обнулял
маску, и для персонажей, чей `taximask` сохранён при старом размере 258, хвост
(28 байт) оставался бы неинициализированным. Добавлено `m_taximask.fill(0)`.

### 1.5. Что проверено после правок

* `tools/check_db2_build.ps1` читает константы **из файлов ядра** — после правок он сам
  перестаёт ругаться: проверяется `BATTLE_PET_SPECIES_MAX_ID >= строк`,
  `MAX_DIFFICULTY >= строк`, `TaxiMaskSize >= ceil(строк/8)`.
* Сигнатура `WDC1` и `LayoutHash` в `ОШИБКИ.txt` не упомянуты — значит, все 242 таблицы
  совпали с `DB2Metadata.h`; трогать их не требовалось.
* Повторного дубля объявлений в заголовках ядра нет (проверено скриптом по всем `.h/.cpp`).

## 2. Аудит кастомного контента: «всё кастомное должно быть реализовано на 100%»

### 2.1. Кастомные расы 31..44 — пять блокираторов из `docs/CUSTOM_RACES_31_44.md`

| # | Блокиратор | Статус | Где проверено |
|---|-----------|--------|---------------|
| 1 | `MAX_RACES 31` → расы 31..44 выпадали из `_playerInfo[MAX_RACES][MAX_CLASSES]` | **ГОТОВО** | `SharedDefines.h:200` — `MAX_RACES 45` |
| 2 | `RACEMASK_*` на 32 бита → сдвиг ≥ ширины `int` для рас 33+ | **ГОТОВО** | `SharedDefines.h` — все маски через `UI64LIT(1)`, есть `RaceMaskForRace()` и `RACEMASK_DB32_LIMIT` |
| 3 | `ObjectMgr::LoadPlayerCreateInfo` требует строку в `ChrRaces.db2` | **ГОТОВО** | `ObjectMgr.cpp:3283-3329` — пропуск через реестр + `displayId` расы-донора |
| 4 | `ObjectMgr::LoadRaceAndClassExpansionRequirements` | **ГОТОВО** | `ObjectMgr.cpp:9968-9976` — `!raceEntry && !Player::IsCustomRace(raceID)` |
| 5 | `Player::TeamForRace / TeamIdForRace / setFactionForRace` | **ГОТОВО** | `Player.cpp:6600-6660` — команда из реестра, `FactionID` от донора |

Дополнительно проверено и **работает**: `Player::IsValidRace` (`Player.h:1583`),
`CharacterHandler.cpp:454-463` (создание персонажа), `ObjectMgr.cpp:3669`
(«заполнение дыр» `player_levelstats`), `CharacterHandler.cpp:504` (маска запрета рас),
`ObjectMgr.cpp:3277/3371/3403/3428/3472/3532/3576/3621/3662/3799/9939` — везде предел
поднят до `MAX_RACES = 45`, массивы объявлены с новой константой.

### 2.2. Найдено новым аудитом и исправлено

1. **`RACEMASK_ALL_PLAYABLE` не содержал кастомных рас.** Из-за этого для рас 31..44
   отбрасывались: `quest_template.AllowableRaces` (`ObjectMgr.cpp:4221`),
   `spell_area.racemask` (`SpellMgr.cpp:2176`), критерии достижений
   (`CriteriaHandler.cpp:111,256`), `mail_level_reward`, `spell_group` и т.д.
   *Исправлено:* маски `RACEMASK_CUSTOM_PLAYABLE` / `RACEMASK_CUSTOM_ALLIANCE` /
   `RACEMASK_CUSTOM_HORDE` вынесены **выше** `RACEMASK_ALL_PLAYABLE` и включены в
   `RACEMASK_ALL_PLAYABLE` и `RACEMASK_ALLIANCE`. `RACEMASK_HORDE`
   (`ALL_PLAYABLE & ~ALLIANCE`) автоматически получает оставшиеся расы.

2. **`DB2Manager::GetChrRaceName()` возвращал `""` для рас 31..44** — `.pinfo`,
   `.lookup race` и логи печатали пустое имя. *Исправлено:* fallback на имя расы-донора.

3. **SQL кастомных рас вообще не подключён к установщику.** Ни `setup.bat`, ни
   `apply_play_sql.ps1` не вызывали `sql/52_custom_races_31_44.sql` — расы были видны
   в окне создания, но `playercreateinfo`, `player_levelstats`,
   `race_unlock_requirement` оставались пустыми (`CHAR_CREATE_FAILED`).
   *Исправлено:* патч добавлен в оба установщика (в `apply_play_sql.ps1` после 48/49).

4. **Расхождение «раса → команда» между тремя источниками.** `worldserver.conf.dist`,
   `docs/CUSTOM_RACES_31_44.md` и `sql/52_…` должны совпадать с `DEFAULT_DEFINITIONS`
   в `Player.cpp` (иначе реестр из конфига и SQL-отчёт разойдутся).
   Согласовано: `39 → HORDE:10` во всех трёх источниках.

## 3. Что осознанно НЕ исправлялось (границы платформы 26124)

Из `docs/FEATURE-AUDIT.md`, проверено по исходникам:

* **Харанир / Вульперы / Механогномы** в клиенте 7.3.5 build 26124 не existуют:
  нет строк DB2 и нет моделей в CASC. Сервер не может выдать то, на что нельзя сослаться.
* **Формы/облики из 8.x/9.x** — та же причина (`SpellShapeshiftForm.db2` + модели в CASC).
* **`sql/legionforge/old/world` (472 файла) и `sql/updates/world/master` (189 файлов)**
  не применяются «оптом» намеренно: ADB_735.10 — снимок от 17.08.2018, слепой прогон
  даёт дубли. Нужен точечный подход (как сделано для 48/49/52).
* **ENV7** — 295 `ScriptName` без C++-скрипта; **ENV8** — 1917 отклонённых SQL;
  **TPL1–TPL4** — 36 шаблонов с `unit_class=0`: inventory в
  `docs/stability/MASTER-INVENTORY.md`, правки данных, не кода.

## 4. Порядок применения исправлений

```bat
rem 1. Пересобрать ядро (константы и маски - время компиляции)
build_server.bat

rem 2. Применить SQL (кастомные расы 31..44 теперь подключены)
powershell -NoProfile -ExecutionPolicy Bypass -File apply_play_sql.ps1

rem 3. Сверить DB2 с ядром (после правок констант должна вернуть код 0)
powershell -NoProfile -ExecutionPolicy Bypass -File tools\check_db2_build.ps1

rem 4. Запуск
play.bat
```

```
>> Registered 14 custom client race(s) (ids 31-44) from CustomRaces.Definitions
```
